## Common problems

**BOTW Archipelago is not in the Archipelago Launcher's list.**
Archipelago is older than 0.6.7, or `botw.apworld` is not installed: **Install APWorld** in the Launcher, then close
it and open it again.

**The first start stops on "Could not download...".**
The first start downloads the libraries the launcher needs, from the internet (files.pythonhosted.org). Check the
connection, or a firewall that blocks Archipelago, then click **Try again**.

**"Add from a room link" does not find your seed.**
Its message says why. Open the link in your browser: it must be the room's page, with the players and their files.
A room unused for a long time is deleted. You can always download your slot file from the page and add it with
**Add a seed...**.

**The launcher refuses your Cemu.**
Its message says what is missing: another version of the game, the update or the DLC not installed, a game listed by
Cemu that moved... Fix it in Cemu, start the game once there, and choose Cemu again.

**"Close Cemu before preparing a session".**
The launcher starts Cemu itself: close yours first.

**Your seed's version is shown in orange.**
The seed was generated by another version of BOTW Archipelago. A newer one: **Update to version X** installs it. A
version before 0.4.0: **Play with version X** opens it next to this one. An older one since: generate the seed again
with this one ([updating](setup_en.md#updating)).

**With mods, the game never finishes loading.**
The game lacks memory. Read what the session's log says about [Extended Memory](mods_en.md#extended-memory), and
check that the same mods load in your own Cemu.

**The game does not react to your controller.**
The profile copied no controller setting from your Cemu. In the game's window, open Cemu's Options > Input settings
and choose your controller for player 1; the profile keeps it.

**The Archipelago logo stays grey.**
The client is not connected to the room. The session's steps and its log, in the launcher's window, say why. The
room's address changes when it restarts on archipelago.gg: take the new one from the room's page.

**The tracker shows something wrong.**
See the [trackers' troubleshooting](poptracker_en.md#troubleshooting).

**A campfire, a free bed or a Great Plateau shrine terminal offers no "A".**
As in the base game, they wait for the Great Plateau Tower, which can be reached from the start.

**The client stops on "WRONG GAME MODE".**
The seed was generated with `master_mode`: its Master Mode chests are locations, and a Normal mode save has none of
them. Load a Master Mode save, or start one with **Master Mode** on the title screen (The Master Trials, DLC 1),
then start the session again.

**"This seed's shrine chests hold their items (shrine_chest_items)..."**
With `shrine_chest_items`, the shrines are built from the base game installed as a folder, and Cemu no longer lists
one: install the base game as a folder again (not as a `.wua` or `.wud` file), or play a seed generated without the
option.

**Generation stops on `vanilla_statues`.**
Its 108 Spirit Orbs need room among the locations: turn on `chest_sanity`, or `korok_sanity` with a lower
`korok_local_filler` (see [Spirit Orbs](en_Breath%20of%20the%20Wild.md#spirit-orbs)).

**On Linux, the launcher refuses my Cemu: "a Flatpak or Snap sandbox".**
The client reads the memory of the Cemu it starts, which a Flatpak or Snap sandbox hides. Use Cemu's official
AppImage, or the `Cemu` of its Linux zip, from [cemu.info](https://cemu.info/), then **Choose Cemu...** again.

**On Linux, the session says it "cannot open /proc/.../mem".**
Linux keeps the client from reading Cemu's memory: `cat /proc/sys/kernel/yama/ptrace_scope` says 2 or 3, where 0
or 1 is needed. `sudo sysctl kernel.yama.ptrace_scope=1` allows it until the next restart. Start Cemu with
**Play**: a Cemu started by hand cannot be read.

**On Linux, Cemu runs at a few frames per second.**
Cemu renders on the processor: your graphics card has no Vulkan driver. `vulkaninfo --summary` (package
`vulkan-tools`) lists only `llvmpipe`. Install your card's driver; on a system started with `nomodeset`, remove it.

## Logs

The launcher's **Logs** page shows what it did, at the level of detail you choose. To
[report a problem](https://github.com/EIdras/BOTW-Archipelago/issues), click **Save a diagnostic...** there and attach
the zip: it holds the launcher's logs and the last session of the seed you last selected (the client's log, Cemu's
log and a summary), no password.

Each session's logs are also in its folder, which **Open the session's folder** opens once the session has ended:
`%LOCALAPPDATA%\BOTW Archipelago\play-seeds\<seed>\sessions\<date>\` on Windows,
`~/.local/share/BOTW Archipelago/play-seeds/<seed>/sessions/<date>/` on Linux.

## Test commands

The client adds a few commands to the session's command line, for tests and bug reports:

| Command | What it does |
|---|---|
| `/ap-tip <text>` | Show a line in the in-game Archipelago journal |
| `/ap-disconnect [s]` | Simulate a server disconnection for `s` seconds |
| `/ap-evt [n\|reset]` | List the game's last event requests |
| `/ap-deathlink [cause]` | Kill Link as a received DeathLink would (sent to nobody) |
| `/ap-border` | With `region_lock`: Link's position, the nearest closed region and the return to safe ground |
